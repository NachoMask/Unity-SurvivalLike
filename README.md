유니티 엔진으로 개발한 뱀파이어 서바이버즈(Vampire Survivors)의 모작. 원작과 동일하게 제한시간까지 몰려드는 적을 상대하며 생존하는 것을 목표로 함. 레벨업을 통해 공격과 패시브를 획득하는 시스템과 반복적으로 등장하는 객체들의 재사용 그리고 청크 및 적의 재배치 구현에 중점을 두었음.

## 핵심 기술 구현

### 1. 오브젝트 풀링을 사용한 객체 재사용
<img width="481" height="181" alt="오브젝트 풀 동작 과정" src="https://github.com/user-attachments/assets/4c16a818-7210-46f8-84d7-c859ce1d38a4" />
<img width="730" height="261" alt="오브젝트 풀 비교 결과" src="https://github.com/user-attachments/assets/c7ae746b-d9a6-44c9-8ab9-3b8700fd6bec" />

#### [문제 상황]
- 장르 특성상 다수의 적과 투사체, 데미지 텍스트가 반복적으로 등장하고 제거됨
- 객체를 매번 생성하고 파괴하면 처리 비용과 메모리 할당이 반복적으로 발생함
- 전투 중 이러한 비용이 누적되는 것을 줄이기 위해, 객체의 생성/파괴 빈도를 낮출 필요가 있었음
#### [해결 과정]
- 자주 생성/파괴되는 적, 투사체, 데미지 텍스트에 Unity의 ObjectPool을 적용해 재사용하도록 구현
- 제거 연출 완료, 투사체 타격 횟수 소진 등 객체별 사용 종료 조건에 따라 풀에 반환하도록 처리
- 반환 및 재사용 과정에서 이동 상태, 투사체 정보, 시각 효과 등을 초기화해 이전 상태가 다음 사용에 영향을 주지 않도록 구현
#### [결과]
- 일반적인 생성/파괴 방식과 풀링 방식을 각각 1분씩 3회 측정하여 성능을 비교함
- 기존 방식 대비 최대 프레임 시간이 약 14%, 객체 생성 호출 수가 약 55.3% 감소함
- 프레임당 평균 GC Alloc이 약 21.9%, 최대 GC Alloc이 약 35.6% 감소하여 Managed Heap의 신규 메모리 할당 부담을 줄임

### 2. 타일맵 청크와 적의 재배치 로직
<img width="775" height="269" alt="재배치_청크 시연" src="https://github.com/user-attachments/assets/2147867b-bf99-48d5-9e88-f36257a1ac6c" />
<img width="561" height="364" alt="재배치_동작 과정" src="https://github.com/user-attachments/assets/a8422b9b-8967-40ed-9c59-0f333d74d8b9" />

#### [문제 상황]
- 플레이어가 어느 방향으로 계속 이동하더라도 필드가 이어지고 적이 계속 몰려와야 함
- 이동 경로를 따라 맵을 계속 추가하면 관리해야 할 맵 객체와 메모리 사용량이 증가할 수 있음
- 멀어진 청크나 적을 처리할 때 반복적인 생성/제거 비용을 줄이고 기존 객체를 활용할 필요가 있음
#### [해결 과정]
- 플레이어 중심의 감지 영역에 설정한 트리거 이벤트를 통해 청크와 적의 영역 이탈을 감지
- 타일맵 청크 4개를 2x2로 배치하고, 청크 전체가 감지 영역을 벗어나면 청크 크기의 2배만큼 반대편으로 이동
- 적은 콜라이더 중심을 기준으로 벗어난 축을 판단하고, 감지 영역의 너비/높이만큼 반대편으로 이동
#### [결과]
- 플레이어의 이동 거리가 늘어나도 청크 수를 일정하게 유지하고, 적을 플레이어 주변에 위치시킴
- 재배치 대상의 위치 비교를 매 프레임 직접 수행하지 않고, 영역 이탈 이벤트가 발생했을 때만 수행하도록 구성
- 재배치 로직을 독립된 컴포넌트로 구성하여, 동일한 이탈 판정 및 재배치 규칙을 사용하는 다른 오브젝트에도 기능을 적용할 수 있음

### 3. 프리팹 기반 공격 로직과 강화 시스템 설계
<img width="523" height="202" alt="pp_3" src="https://github.com/user-attachments/assets/dbd5cecf-d472-4006-863e-e7bfcdaf38db" />

#### [문제 상황]
- 공격마다 동작 방식과 적용 능력치가 달라, 공격별 동작과 설정을 구분해 관리할 필요가 있었음
- 능력치와 강화 상승 수치를 코드에 고정하면, 이를 조정할 때마다 코드를 수정해야 하는 불편함 
- 서로 다른 공격 로직에서도 강화와 관련된 동작을 일관된 방식으로 처리할 필요가 있음
#### [해결 과정]
- 공격 로직을 담당하는 컴포넌트를 프리팹으로 구성하고, 기본 능력치와 레벨별 강화 수치를 직렬화하여 공격별로 설정
- 강화 시 해당 레벨의 상승 수치를 적용하고, 최종 능력치 계산에 반영하여 공격 로직에 반영함
- IPlayerAttackUpgradeable 인터페이스를 구현한 각 공격 로직은 강화 가능 여부 확인이나 강화 적용을 공통된 방식으로 처리함.
#### [결과]
- 기존 공격의 기본 능력치와 레벨별 강화 수치를 코드 수정 없이 인스펙터에서 조정할 수 있음
- 동일한 공격 동작을 사용하는 프리팹에 서로 다른 공격 및 강화 수치를 설정할 수 있음
- 공통 인터페이스를 구현한 새 공격을 추가하면, 기존 강화 시스템에 새 분기를 추가하지 않아도 연결이 가능
