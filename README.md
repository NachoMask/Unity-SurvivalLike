## 1. 반복 생성 객체의 오브젝트 풀링 적용

### 문제

장르 특성상 다수의 적과 투사체 그리고 그에 따른 데미지 텍스트가 빈번하게 표시된다. 결과적으로 전투 규모가 커질수록 객체 생성과 삭제에 대한 호출과 메모리 할당이 함께 증가했다. 특히 수명이 짧은 객체는 매번 새로 생성해 초기화하고 사라지는 과정에서 비용이 반복적으로 발생했기 때문에 이런 객체들에 대한 특별한 관리가 필요했다.

### 해결

<img width="481" height="225" alt="오브젝트 풀 동작 과정" src="https://github.com/user-attachments/assets/c5aa0ff0-d087-43a9-ac7f-ac0111461a46" />

적, 투사체, 데미지 텍스트처럼 자주 생성하고 제거되는 객체를 풀이라는 별도의 공간으로 관리하는 오브젝트 풀링을 도입했다. 풀링으로 관리되는 객체를 꺼내 사용할 때는 용도에 맞게 초기화해야 한다.

적 객체의 경우 스탯 데이터, 스폰 위치, 렌더링 상태를 설정하고 오브젝트를 활성화해서 사용한다. 적이 처치되면 객체를 제거하는 대신 풀로 반환하며 코루틴, 물리 속도, 충돌 상태 등을 비활성화하여 보관한다.

투사체나 데미지 텍스트도 마찬가지로 생성을 담당하는 클래스에서 전용 풀을 통해 관리된다. 사용 시 풀에서 꺼낸 객체에게 필요한 정보를 넣어 초기화하고 역할을 마치고 반환되면 다시 사용할 수 있도록 정리하는 과정을 거친다.


### 결과

<img width="730" height="261" alt="오브젝트 풀 비교 결과" src="https://github.com/user-attachments/assets/dc353a7a-f223-4514-bdae-e9a4346db2b5" />


풀링 방식과 풀 없이 객체 생성 및 제거를 수행하는 두 방식을 동일한 조건에서 3회씩 측정해 평균 결과를 비교했다. 평균 프레임 시간은 동일하며 최대 프레임 시간은 소폭 감소하는 모습을 보였다.

풀링을 적용한 경우 객체 생성 호출이 약 55.3% 감소했으며 풀링은 객체를 제거하는 대신 풀에 반환하므로 객체 제거 호출은 측정 구간에서는 발생하지 않았다. 결과적으로 전체 생성 및 삭제 호출을 약 76.5% 줄였다.

프레임 당 평균 GC Alloc은 약 21.9%, 최대 GC Alloc은 약 35.6% 감소하여 힙에 할당한 평균 메모리 크기도 효과적으로 줄었다.

## 2. 오브젝트 재배치를 통한 무한 맵 구현

### 문제

이동 가능한 넓은 필드를 실제 크기대로 생성하면 타일 맵과 적 오브젝트가 계속해서 누적된다. 이는 메모리 사용량과 생성, 삭제 비용을 증가시키며 플레이 시간이 길어질수록 성능 저하를 일으킨다.

따라서 제한된 수의 오브젝트만으로 필드를 지속적으로 표현할 수 있는 방법이 필요했다.

### 해결

<img width="561" height="364" alt="재배치_동작 과정" src="https://github.com/user-attachments/assets/77e834b4-1a96-467a-99fc-04266fd132cb" />


플레이어를 중심으로 사각형의 감지 영역을 만들고 이 범위를 벗어나는 오브젝트를 재배치하는 로직을 만들었다.

감지 영역의 중심과 재배치할 대상의 위치 차이를 계산해서 대상을 영역 내 플레이어 카메라 바깥에 배치하도록 동작한다. 감지 영역과 오브젝트 간의 충돌 트리거 이벤트가 발생했을 때만 재배치를 수행하기 때문에 매 프레임 오브젝트와 플레이어 간의 거리를 계산하는 방식을 피하고 재배치가 필요한 시점에만 로직을 실행하도록 최적화했다.

### 결과

<img width="1162" height="403" alt="재배치_청크 시연" src="https://github.com/user-attachments/assets/e6c25599-21c3-4d4b-b7c6-68bd69ba415c" />


4개의 타일 맵 청크에 재배치 로직을 적용하여 플레이어가 이동하는 방향을 따라 계속해서 위치를 변경함에 따라 무한 맵을 표현했다. 새로운 청크를 반복해서 생성하거나 제거하지 않기 때문에 맵 크기에 관계없이 타일 맵 오브젝트 수를 일정하게 유지할 수 있었다.

적이 범위 밖으로 벗어나면 플레이어 주변으로 재배치해 멀어진 적이 불필요하게 방치되는 상황을 방지했다. 재배치 로직을 컴포넌트 형태로 만들었기 때문에 추후 재배치 기능이 필요한 다른 오브젝트가 있다면 이를 부착한 뒤 설정값만 조정해 재사용할 수 있다.
